# MDPilot

A closed-loop scientific reasoning agent for molecular dynamics.

> An MD operator runs the simulation you describe.
> An MD scientist decides what to simulate next.
> MDPilot is the latter.

Existing MD agents solve the inner loop — setup, submit, analyze. MDPilot owns
the outer loop: read the diagnostics, judge whether the trajectory answers the
question that was asked, and decide the next run. Extend? Stop? Or is vanilla MD
inadequate and the campaign needs enhanced sampling?

## What it does

**Runs a campaign end to end.** `run_campaign()` simulates, diagnoses, decides,
and repeats — persisting every round to disk. One LLM call per round, at the
decide step only. Everything else is deterministic Python.

**Judges convergence on real statistics.** Block averaging, integrated
autocorrelation time and ESS, and two independent estimates of statistical
inefficiency that must agree or the agent is told to flag it.

**Detects the failure mode convergence metrics cannot see.** A metastable basin
reads as a converged plateau — low variance, flat mean, apparently settled. An
exploration diagnostic (Sarle's bimodality coefficient with an occupancy gate)
separates *pinned in one basin* from *not yet converged*, so "extend" and
"switch to enhanced sampling" become distinguishable decisions.

**Designs its own collective variable.** On `switch_to_metad` the agent proposes
which coordinate is slow — a chemistry judgment — as MDTraj selection strings.
Deterministic code resolves that against the real topology and rejects unknown
CV types, empty selections, and wrong arity before a single step is run. Atom
indices, hill widths, heights and bias factors never pass through the LLM.

**Runs well-tempered metadynamics.** PLUMED input is generated by a typed writer
with validated invariants, not string templating. γ = 10 by default; plain
metadynamics is not constructible, because it does not converge to the free
energy surface.

**Doesn't care which engine ran it.** OpenMM and GROMACS sit behind one
`MDAdapter` Protocol and produce the same diagnostics from the same benchmark.

**Sets systems up properly.** PDBFixer → solvate → minimize → staged NVT heating
(50 K → 300 K) → NPT density relaxation → production, on both engines, with an
inspectable per-stage trace. Setup is cached, so resume costs a stat rather than
a re-minimization.

**Survives restarts.** Per-campaign SQLite holds config, per-round diagnostics,
decisions and the hypothesis ledger. A killed campaign resumes at round *k+1*,
and a resume whose system spec doesn't match the recorded one is refused.

**Uses the GPU when there is one.** The platform is probed for actual usability,
not just registration, and falls back to CPU cleanly. Measured on 4810 atoms:
**299 ns/day on CUDA vs 11.4 ns/day on CPU.**

## Status

Milestones 1–3 complete and verified live: the closed loop runs, campaigns
resume from disk, and the same benchmark runs through either engine unchanged.

Milestone 4 (sampling-strategy decisions) — the full path from diagnostic to
biased trajectory executes, and well-tempered metadynamics is verified against
PLUMED's own output: hill heights decay 1.386 → 0.577 kJ/mol as the bias
accumulates to 19.7 kJ/mol. The done-criterion — the agent detecting inadequacy
on a system that genuinely requires enhanced sampling, and the biased run
crossing a barrier vanilla MD could not — is **not yet met**. See
[`ROADMAP.md`](ROADMAP.md).

## Setup

Python 3.10+ and an Anthropic API key. A CPU OpenMM build is enough for
vanilla MD.

```sh
python3 -m venv .venv
.venv/bin/pip install -e .
cp .env.example .env  # then set ANTHROPIC_API_KEY
```

### Metadynamics needs conda

`openmm-plumed` is not on PyPI, so the venv above cannot run biased simulations —
anything reaching `switch_to_metad` will raise.

```sh
export MAMBA_ROOT_PREFIX=$HOME/.micromamba
micromamba create -y -n mdpilot -c conda-forge \
    python=3.12 openmm openmm-plumed plumed mdtraj pdbfixer pyyaml \
    python-dotenv pytest numpy scipy
micromamba run -n mdpilot pip install anthropic
micromamba run -n mdpilot pip install --no-deps -e .
```

**On a CUDA machine, pin the toolkit to your driver.** conda-forge may install an
NVRTC newer than the driver supports, which registers the CUDA platform and then
fails at kernel load with `CUDA_ERROR_UNSUPPORTED_PTX_VERSION`. Check
`nvidia-smi` for the supported CUDA version and match it:

```sh
micromamba install -y -n mdpilot -c conda-forge "cuda-version=13.2"
```

The two environments pin different OpenMM builds and are not interchangeable.

## Run a campaign

```python
from pathlib import Path
from mdpilot.orchestrator.loop import run_campaign

result = run_campaign(
    work_dir=Path("campaigns/demo"),
    initial_steps=10_000,   # 20 ps at 2 fs
    max_rounds=1,
)
print(result.rounds[0].decision)
```

First call fetches PDB 1L2Y, solvates, minimizes and equilibrates; the state is
cached, so later calls on the same `work_dir` skip straight to dynamics.
Per-round artifacts land in `campaigns/demo/rounds/`.

## Tests

```sh
pytest tests/unit          # 130 tests, ~4 s — no API key, no MD
pytest tests/integration   # live MD; PLUMED and API-key tests skip if unavailable
```

Integration coverage includes equilibration physics (velocities, temperature,
barostat, density) and metadynamics against PLUMED's own HILLS and COLVAR
output. Both run without an API key. Reference trajectories for the
Milestone-1 criterion are generated on demand:

```sh
python -m benchmarks.generate_trpcage_planted --traj under       # 50 ps
python -m benchmarks.generate_trpcage_planted --traj converged   # 5 ns
```

They land in `benchmarks/data/trpcage/` (gitignored; deterministic given the
seed). Note these predate the equilibration work and are NVT — see F3 in
[`docs/activity-log.md`](docs/activity-log.md).
